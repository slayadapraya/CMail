# CMail 0.8.1 — Sync bugfix + Concept C layout

CMail is still in progress and experimental. This release includes the Concept C interface update and fixes Calendar loading on newly connected devices.

## Bug fixed

Calendar and Contacts refresh previously ran an inbox sync first. A slow initial mail import, an inbox sync error, or a Gmail quota pause could stop Calendar before its own API request ran—even when Calendar permission was granted and the Google Calendar API was working. Calendar refresh requests queued behind a failed mail sync could also be lost.

## What changed

- Calendar and Contacts now sync independently of the inbox import.
- Google quota pauses are tracked separately for Gmail, Calendar, and People.
- Queued Calendar refreshes survive an inbox sync failure.
- Calendar has a visible **Refresh calendar** button and clearer sync status.

## Layout and compact inbox update

- Concept C header, flat icon toolbar, tooltips, and subtle hover fades.
- Cleaner sidebar, inbox, reader, and Calendar surfaces; CMail Blue theme preset.
- Settings → Inbox row style: current-sized message cards or compact single-line rows.
- Movable tabs, split panels, standalone windows, custom colours, scaling, and low-power rendering remain available.

## Install or update on Ubuntu

Download `cmail_0.8.1_all.deb` from this release, close CMail, then run in the download folder:

```bash
sudo apt install ./cmail_0.8.1_all.deb
cmail
```

Existing local account configuration and mailbox caches are preserved. Open Calendar and click **Refresh calendar**. Google Calendar requires Google browser/OAuth sign-in; the Gmail app-password connection supports mail only.

## Validation

- 56 unit tests passed.
- Native UI regression: Calendar loads during a Gmail quota pause and after a queued inbox sync fails.
- Native docking regression: panel splits, detached windows, and re-docking work.
- Both inbox row styles tested with 10,000 synthetic cached conversations.

The release contains app code and an installer, not account credentials, OAuth JSON, tokens, mailbox caches, or personal event data.
